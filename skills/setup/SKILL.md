# SWOT News — онбординг

Скрипт: `${CLAUDE_PLUGIN_ROOT}/scripts/fetch_kagi_api.py`.
References: `${CLAUDE_PLUGIN_ROOT}/skills/setup/references/`.
Шаблоны: `${CLAUDE_PLUGIN_ROOT}/skills/setup/assets/`.

Этот скилл **задаёт вопросы** — в отличие от `/swot-news:daily`. Внутри себя
`daily` не вызывать: у него противоположная политика вопросов.

Режимы (аргумент):
| Аргумент | Что делает |
|----------|-----------|
| без аргумента | полный онбординг; конфиг уже есть → предложить режим на выбор |
| `--recheck` | только шаги 3 и 5: пересобрать список категорий и кластеры |
| `--profile` | только шаги 1, 2 и перезапись `Контекст.md`; категории не трогать |
| `--reset` | полный онбординг с нуля; существующий конфиг перезаписать после подтверждения |

**Ничего не записывать на диск до шага 6** (единственное исключение — `catalog.json`
на шаге 3). Онбординг прерван раньше — в папке пользователя не должно остаться следов.

## Шаг 0 — площадка

1. `pwd` — рабочая папка. Это будущий `base_dir`. Если она явно не подходит
   (домашняя папка, корень диска, папка репозитория с кодом) — предложить
   подпапку, например `./SWOT`, и спросить одной репликой.
2. Интерпретатор Python: `python3 --version`, при неудаче `python --version`,
   затем `py -3 --version`. Ни один не сработал → сказать: «Нужен Python 3.9+:
   https://www.python.org/downloads/ — после установки запусти меня снова», КОНЕЦ.
   Дальше `{PY}` = сработавший вызов.
3. Obsidian: `ls -a` — есть ли папка `.obsidian/` здесь или у родителя.
   Есть → `obsidian.enabled = true` (wikilinks, callouts, предложение `.base`).
   Нет → `false` (чистый Markdown). Сообщить пользователю выбранный режим одной
   строкой и дать возможность возразить.
4. Существующий конфиг: `ls .swot-news/config.json`. Есть и аргумента нет →
   показать текущие настройки (категории, кластеры, объём) и спросить
   `AskUserQuestion`: «Пересобрать категории (--recheck)» / «Поправить профиль
   (--profile)» / «Настроить заново с нуля (--reset)» / «Ничего не менять».

## Шаг 1 — анализ папок интересов

Только чтение, жёсткие бюджеты — цель понять, чем человек занят, а не изучить архив:

| Что | Бюджет |
|-----|--------|
| Имена `.md`-файлов рекурсивно (`Glob **/*.md`) | ≤300 имён; больше — сказать «файлов много, смотрю верхний уровень» и взять 2 уровня вложенности |
| Названия папок верхних двух уровней | все |
| Теги: `Grep "#[\w/-]+"` по `.md` | топ-30 по частоте |
| Файлы целиком | **≤8 штук**, отбирать по именам, похожим на профиль: `README`, `О себе`, `Профиль`, `Цели`, `Планы`, `About`, `Now`, `Goals` |

Папка пустая или `.md` нет — шаг пропустить молча, гипотезы не будет.

Результат — гипотеза интересов **5–7 строками** в чат:
«Похоже, ты: {занятие}; часто пишешь про {темы}; вероятная локация {страна}».
И одна реплика: «Так? Поправь, если мимо — дальше я спрошу точнее».

Файлы пользователя не пересказывать и не цитировать дословно: из них берутся
только выводы о темах.

## Шаг 2 — интервью

По `references/interview.md`: три вызова `AskUserQuestion` (варианты адаптировать
под гипотезу шага 1), затем свободным текстом — темы «Мониторить ежедневно»
и подтверждение собранного профиля.

## Шаг 3 — проход по направлениям Kagi

```bash
{PY} "${CLAUDE_PLUGIN_ROOT}/scripts/fetch_kagi_api.py" --list-categories --out .swot-news/catalog.json
```

Каталог живой (~165 категорий, состав меняется). Файл ~16 КБ — читать целиком можно.

Дальше строго по `references/category-selection.md`: три уровня (блоки →
категории внутри выбранных блоков → гео и локальные ленты), валидация
`12 ≤ N ≤ 60` с комфортным окном 25–40. `AskUserQuestion` здесь **не использовать** —
вариантов десятки, общение таблицами и номерами.

Итог шага — плоский список `category_id` через запятую и число кластеров `n`.

## Шаг 4 — проба обогатителя

Обогатитель проверяет темы «Мониторить ежедневно» свежим веб-поиском.

- Раздел «Мониторить ежедневно» пуст → `enricher.tool = "off"`, шаг пропустить.
- Иначе — один пробный вызов `mcp__brave-search__brave_web_search`
  (`query: "test"`, `count: 1`). Ответ пришёл → `"brave"`. Инструмент недоступен
  или ошибка → `"websearch"`. Нативного веб-поиска тоже нет → `"off"`
  и сказать об этом одной строкой.

## Шаг 5 — кластеры

```bash
{PY} "${CLAUDE_PLUGIN_ROOT}/scripts/fetch_kagi_api.py" --build-clusters -n {n} --categories "{список}"
```

Показать таблицу: кластер, ярлык, число категорий, вес, сами категории;
плюс `balance_ratio`. Спросить одной репликой: «Оставить / пересобрать
с другим числом кластеров / перекинуть категорию X в кластер Y».
Ручная перекидка — правка списков в JSON перед записью, скрипт заново не гонять.

`categories_missing` непустой (категория исчезла из каталога) — просто сообщить,
из выбора её убрать.

## Шаг 6 — запись

Только здесь появляются файлы. `{база}` = папка из шага 0.

| Файл | Источник |
|------|----------|
| `{база}/Контекст.md` | `assets/Контекст.md`, плейсхолдеры `{{…}}` заполнить ответами шагов 1–2. **Ни одного плейсхолдера в готовом файле остаться не должно**; нет данных — строку удалить целиком |
| `{база}/_Watchlist.md` | `assets/_Watchlist.md` |
| `{база}/SWOT.md` | `assets/SWOT.md` |
| `{база}/{Силы,Слабости,Возможности,Угрозы}/` | пустые папки (`mkdir -p`) |
| `{база}/Выпуски/` | пустая папка |
| `{база}/.swot-news/config.json` | `assets/config.template.json` + результаты шагов 0, 3–5 |
| `{база}/swot-all.base` | `assets/swot-all.base` — **только** при `obsidian.enabled` и только с согласия пользователя (спросить одной репликой) |

Конфиг: `base_dir` — абсолютный путь; `timezone` — IANA-имя из ответа о локации
(`Europe/Berlin`, `America/New_York`; не уверен — `null`, тогда берётся системное
время); `entries_budget` — из ответа про объём; `clusters` — результат шага 5
(`label` + `categories`, без служебных полей `weight`/`names`).

Файл уже существует и это не `--reset` — спросить, перезаписать или оставить.
`Контекст.md` при `--recheck` **не трогать**.

## Шаг 7 — разрешения (опционально)

Показать `assets/settings-snippet.json` и объяснить одной фразой: без него
Claude Code будет спрашивать разрешение на каждый запуск скрипта сбора.
С согласия — **смержить** массив `permissions.allow` в
`{база}/.claude/settings.local.json` (файл есть → дописать недостающие строки,
существующие настройки не перезаписывать; нет → создать).
Отказ — принять молча, плагин работает и так.

## Шаг 8 — смоук и финал

```bash
{PY} "${CLAUDE_PLUGIN_ROOT}/scripts/fetch_kagi_api.py" --self-check
{PY} "${CLAUDE_PLUGIN_ROOT}/scripts/fetch_kagi_api.py" --check-freshness
```

`ok: false` → показать `problems` и как чинить. `ok: true` → короткий итог:

```
Готово. {N} категорий в {n} кластерах, выпуски → {база}/Выпуски/.
Первый выпуск: /swot-news:daily
Батч Kagi выходит ~12:00 UTC (у тебя ~{локальное время}) — запускай после него.
```

`/swot-news:daily` **не вызывать** — пользователь запустит сам.
Правки профиля потом — руками в `Контекст.md` или в диалоге после дайджеста.
