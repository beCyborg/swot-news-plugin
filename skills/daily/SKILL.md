# SWOT News — ежедневный дельта-пайплайн

Скрипт: `${CLAUDE_PLUGIN_ROOT}/scripts/fetch_kagi_api.py`.
References: `${CLAUDE_PLUGIN_ROOT}/skills/daily/references/`.

Все шаги — **без вопросов пользователю** (`AskUserQuestion` запрещён frontmatter'ом):
прогон обязан завершаться сам, иначе запуск по расписанию зависнет.

Аргумент `--force` — игнорировать анти-заглушку и перезаписать сегодняшний выпуск.

## Интерпретатор Python

Скрипт запускается любым из `python3` / `python` / `py -3`. Первый вызов —
`python3`; «command not found» → пробовать `python`, затем `py -3` (Windows).
Ни один не сработал — одна строка в чат: «Python не найден, нужен Python 3.9+:
https://www.python.org/downloads/», КОНЕЦ. Дальше `{PY}` = сработавший вызов.

## Фаза 0 — гейт конфигурации

```bash
{PY} "${CLAUDE_PLUGIN_ROOT}/scripts/fetch_kagi_api.py" --self-check
```

Скрипт сам ищет конфиг: `SWOT_NEWS_CONFIG` → `./.swot-news/config.json` →
вверх по дереву папок.

- Выход `2` / `"error": "config_not_found"` → напечатать **ровно одну строку**:
  «Конфиг не найден — сначала запусти `/swot-news:setup` в рабочей папке».
  **КОНЕЦ. Ничего не создавать: ни файлов, ни папок.**
- `"ok": false` → одна строка с первым элементом `problems` и подсказкой
  `/swot-news:setup --recheck`. КОНЕЦ.
- `"ok": true` → запомнить из ответа: `base_dir`, `issues_dir`, `today`,
  `enricher`, `obsidian`, `clusters`, `categories_missing_share`.

Дальше `{база}` = `base_dir`, `{выпуски}` = `issues_dir` из этого ответа.
Полную схему конфига читать не нужно — всё нужное уже в `--self-check`.

## Фаза 1 — анти-заглушка

```bash
{PY} "${CLAUDE_PLUGIN_ROOT}/scripts/fetch_kagi_api.py" --check-freshness
```

Свежесть = `batch_id` батча отличается от `batch_id` последнего выпуска;
вторичный предикат — `fresh_by_time` (батч вышел после `batch_hour_utc` сегодня).

`fresh: false` и нет `--force` → НЕ создавать выпуск: одна строка в чат
(«SWOT отложен: батч {dateSlug} не новее последнего выпуска, следующий — завтра»).
**КОНЕЦ.**

## Фаза 2 — сбор данных

```bash
{PY} "${CLAUDE_PLUGIN_ROOT}/scripts/fetch_kagi_api.py"
```

stdout — компактная сводка JSON: `clusters` (ключ → `label`, `file`,
`categories`, `stories`), `meta_file`, `chaos_index`, `categories_missing`.
Прочитай её из результата Bash — пути кластер-файлов берутся **только оттуда**.

`total_stories == 0` или `"error"` → одна строка в чат, КОНЕЦ.

**Кластер-файлы (1–4 МБ) в основной контекст НЕ читать НИКОГДА** — только
передавать субагентам путём. Из `meta_file` можно читать всё, он маленький.

## Фаза 3 — живой контекст

По `references/context-loading.md`, раздел «Живой контекст»: `{база}/Контекст.md`
целиком плюс `context.extra_files`, если заданы. Бюджет ≤300 строк.

## Фаза 4 — база известного

По `references/context-loading.md`, раздел «База известного»: активные карточки
(frontmatter + первая строка Сути) → `_Watchlist.md` → заголовки записей
2 предыдущих выпусков → строки `> 💬` из последнего выпуска.

## Фаза 5 — параллельный анализ

ОДНИМ сообщением запустить всех субагентов (один уровень, без вложенности):

- по одному `subagent_type: swot-news:analyst` на каждый кластер из фазы 2.
  Каждому в промпт: путь к ЕГО кластер-файлу + список его категорий,
  путь к `meta_file`, сжатый профиль с интересами/неинтересами, список
  известных тем (ID карточек + суть одной строкой, темы watchlist, заголовки
  2 последних выпусков), текущий год. **Содержимое JSON в промпт не вставлять —
  только пути.** Явно повторить в промпте: «кластер-файл целиком не читать».
- один обогатитель, если в Контексте непустой раздел «Мониторить ежедневно»:
  `enricher` = `brave` → `swot-news:enricher-brave`;
  `websearch` → `swot-news:enricher-web`; `off` → не запускать.
  В промпт: 2–3 темы с одной строкой «что известно на вчера» + сегодняшняя дата.

**Fallback:** тип агента не найден («Agent type not found») → запустить тех же
как `general-purpose`, вставив в промпт содержимое соответствующего файла из
`${CLAUDE_PLUGIN_ROOT}/agents/` (разделы «Как работать» и формат выхода)
и явно запретив чтение кластер-файлов целиком.

Синтез в основном контексте: слияние кандидатов, дедуп между аналитиками
(одна тема из двух кластеров = одна запись), **бюджет выпуска = `entries_budget`
записей суммарно** (меньше — лучше; пустые квадранты пропускать), данные
обогатителя — в дельты соответствующих записей, TOWS, радар.
Язык и тон — строго по «Языковым правилам» из `references/daily-note-template.md`.

## Фаза 6 — выпуск дня

Файл `{база}/{выпуски}/{note_prefix}{today}.md` строго по
`references/daily-note-template.md`; синтаксис ссылок и callout'ов — по
`references/markdown-modes.md` (`obsidian: true` → wikilinks и callouts,
`false` → обычный Markdown и `<details>`).

Папки `{выпуски}` нет — создать (`Write` создаёт родительские папки).
Идемпотентность и сохранение строк `> 💬` — в том же шаблоне, раздел
«Идемпотентность записи». Писать одним `Write`, целиком.

ID карточек — `{S|W|O|T}-{ГГГГ}-NNN`, где ГГГГ = год из `today`.

## Фаза 7 — агрегация в базу SWOT

Строго по `references/aggregation-rules.md`, в указанном там порядке операций:
чистка watchlist → match с карточками → промоушен → новые темы → затухание.
Чистка watchlist выполняется **каждый** прогон, даже когда новых тем нет.

## Фаза 8 — дайджест

По `references/dialog-protocol.md`: TL;DR, топ-3 дельты, 1–2 факта кругозора,
строка о деградациях (если были), 2–3 открытых вопроса обычным текстом,
маркер «На сегодня всё». Ход ЗАВЕРШИТЬ сразу — без блокирующих вопросов.
Если пользователь потом ответит — там же протокол диалога.

## Ограничения и факты

- Батч Kagi выходит ~12:00 UTC ежедневно; изредка бывает второй батч в тот же
  день (`dateSlug` с суффиксом `.2`) — анти-заглушка по `batch_id` и правило
  идемпотентности это покрывают. Запускать имеет смысл через 1–3 часа после
  выхода батча по местному времени.
- API публичный, без ключа, статус beta; скрипт уважает `Retry-After` при 429.
  Данные CC BY-NC 4.0: некоммерческое использование, атрибуция в футере выпуска
  обязательна.
- `categories_missing_share > 0.2` → в дайджест строку про
  `/swot-news:setup --recheck` (см. dialog-protocol.md).
- Стоимость прогона снижается: меньше кластеров в конфиге, меньше
  `entries_budget`, пустой раздел «Мониторить ежедневно» (обогатитель не стартует).
