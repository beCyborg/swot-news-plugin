# Агрегация находок дня в базу SWOT

Вход: финальные записи дня (после синтеза и дедупа). Для каждой записи — ровно один
из трёх путей: match с карточкой, watchlist, или ничего (слабый сигнал остаётся
только в выпуске дня).

## 1. Match с активной карточкой

Match определяется семантически: та же тема/процесс, даже если формулировка иная.
При сомнении — НЕ матчить: лучше watchlist, чем ложное склеивание двух разных тем.

При match:
- append в `## История`: `- **{дата}** — {дельта одной строкой} ([[{выпуск дня}]])`;
- **не более одной строки Истории на дату**: строка с сегодняшней датой уже есть
  (повторный прогон) — заменить её, не добавлять вторую;
- сила сигнала изменилась → обновить `impact`/`likelihood`/`confidence` во frontmatter;
- обновить `last_reviewed: {сегодня}`.

## 2. Нет match → watchlist

Файл `{база}/_Watchlist.md`, таблица:

```
| Тема | Тип | Первое | Последнее | Дней | Категории | Источников | Выпуск |
|------|-----|--------|-----------|------|-----------|------------|--------|
```

- Темы в watchlist нет → новая строка: Первое = Последнее = сегодня, Дней = 1.
- Тема есть и появилась сегодня снова → Последнее = сегодня, Дней +1,
  ссылку на выпуск заменить на сегодняшний.
- Тема есть, но сегодня не появилась → строку не трогать (кроме чистки ниже).

### Чистка watchlist — обязательный шаг каждого прогона

Выполнять **всегда**, даже если новых тем сегодня нет. Без этого файл разрастается
до сотен килобайт и начинает съедать контекст следующих прогонов.

1. Прочитать все строки таблицы.
2. Удалить строку, если `сегодня − Последнее > 7 дней` — сигнал умер.
3. Колонки `Последнее` нет (файл старого формата) — считать `Последнее = Первое`
   и применить то же правило; таблицу пересобрать в новом формате.
4. После чистки строк всё ещё больше 60 — оставить 60 с самой свежей датой
   `Последнее`, остальные удалить.
5. В дайджест дня добавить строку «watchlist: +{N} новых, −{M} удалено, всего {K}».

## 3. Промоушен watchlist → карточка

Только при: **Дней ≥ 2** ИЛИ сильный мультисточниковый сигнал за один день
(≥3 независимых категорий/источников И impact ≥4).

Создать карточку по `swot-card-template.md`, строку из watchlist удалить,
все даты появления из watchlist перенести в `## История` карточки.

## 4. Затухание карточек

При каждом прогоне проверить активные карточки по `last_reviewed`:
- без упоминаний **≥14 дней** → append в Историю:
  `- **{дата}** — сигнал затухает, {N} дней без упоминаний`;
- без упоминаний **≥30 дней** → `status: archived` (файл не удалять).

Дни считать от `last_reviewed`; помечать затухание не чаще раза в неделю на карточку.

## 5. Порядок операций (важен)

1. Чистка watchlist (п. 2) — до добавления сегодняшних тем, чтобы не удалить
   только что добавленное.
2. Match → обновление карточек.
3. Промоушен из watchlist.
4. Добавление новых тем в watchlist.
5. Проверка затухания.

Все правки — точечные (`Edit`), а не перезапись файлов целиком: в карточках
и watchlist есть ручные правки пользователя, их нельзя терять.
