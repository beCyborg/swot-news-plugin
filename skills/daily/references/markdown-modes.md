# Два режима рендера Markdown

Плагин пишет обычные `.md`-файлы. Синтаксис зависит от флага `obsidian.enabled`
в `.swot-news/config.json` (ставится на онбординге по наличию папки `.obsidian/`).

Шаблоны в остальных reference-файлах написаны в **obsidian-режиме**.
В plain-режиме применяй таблицу замен ниже — смысл и структура не меняются,
меняется только синтаксис.

| Что | obsidian: true | obsidian: false (plain) |
|-----|----------------|--------------------------|
| Ссылка на выпуск | `[[SWOT_2026-08-08]]` | `[SWOT_2026-08-08](SWOT_2026-08-08.md)` |
| Ссылка на карточку из выпуска | `[[T-2026-001 Название]]` | `[T-2026-001 Название](../Угрозы/T-2026-001%20Название.md)` |
| Ссылка на карточку из `_Watchlist.md` / `Контекст.md` (лежат в корне базы) | `[[T-2026-001 Название]]` | `[T-2026-001 Название](Угрозы/T-2026-001%20Название.md)` |
| Ссылка на выпуск из карточки | `[[SWOT_2026-08-08]]` | `[SWOT_2026-08-08](../Выпуски/SWOT_2026-08-08.md)` |
| Картинка с шириной | `![\|420](url)` | `![](url)` |
| Callout `[!abstract]` | `> [!abstract] TL;DR …` | `> **TL;DR** …` (обычная цитата) |
| Callout `[!info]` / `[!note]` | `> [!info] Заголовок` | `> **Заголовок**` |
| Сворачиваемый callout `[!note]-` | `> [!note]- Заголовок` | `<details><summary>Заголовок</summary>` … `</details>` |
| Frontmatter | YAML между `---` | то же самое (YAML читают все редакторы) |

## Правила, общие для обоих режимов

- **Пробелы в путях plain-ссылок кодировать как `%20`** — иначе ссылка не откроется
  в GitHub, VS Code и большинстве просмотрщиков Markdown.
- **Ссылку ставить только на реально существующий файл.** Нет карточки — писать
  ID/название обычным текстом без ссылки. Битые ссылки хуже их отсутствия.
- Таблицы, списки, `**жирный**`, заголовки `##` — одинаковы в обоих режимах.
- Картинки не скачивать: только внешний embed по URL из данных Kagi.

## Сворачиваемый блок в plain-режиме — образец

```markdown
<details>
<summary>Debiasing — 7 вопросов</summary>

1. Какие факты противоречат моей оценке? — {ответ}
2. …

</details>
```

Пустая строка после `<summary>` и перед `</details>` обязательна — без неё
Markdown внутри блока не отрендерится.
